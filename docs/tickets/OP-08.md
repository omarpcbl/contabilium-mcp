## 1. Mejoras de la Versión v3 (Corrección de Fondo)

Tras la segunda ronda de auditoría, se eliminaron los falsos positivos y se reordenó la jerarquía de inferencia:
1. **Precondiciones estrictas en Defectos Conocidos (Cero falsos positivos):**
   * **`DEF-C15`:** Solo se dispara si `StockReservado > StockActual` **Y** la API devuelve `0` en existencias disponibles con reserva (`StockConReservas === 0`). Nunca ante stock negativo sin reservas.
   * **`DEF-C11`:** Solo se dispara si el cliente fue creado por la orden, con CUIT válido (11 dígitos) y sin ficha previa en Contabilium, pero la API le asignó "Consumidor Final". No se dispara si el cliente ya existía registrado como Responsable Inscripto.
   * **`DEF-C6`:** Solo se evalúa como **último recurso** tras descartar fehacientemente C3 (borrador previo), C5 (parámetro nro erróneo) y C7 (integración equivocada). Nunca tapa un error de contrato del partner.
2. **Jerarquía Estricta de Estados (`estado`):**
   1. **`BLOQUEANTE_DETECTADO`:** Errores en datos del partner (CUIT/DNI inválido, depósito inexistente, SKU inexistente, stock insuficiente). Tienen máxima prioridad.
   2. **`ERROR_CONTRATO_PARTNER`:** Errores en la llamada HTTP (C1 endpoint incorrecto, C2 condición de venta no coincide, C5 nro con ID interno en vez de referencia, C7 idIntegracion de otra integración, C9 CUIL enviado a cliente RI, C12 tipo de integración o fecha no ISO).
   3. **`DEFECTO_CONOCIDO_PRODUCTO`:** Defectos verificados de Contabilium (C11, C15, C17, C6).
   4. **`COMPROBANTE_YA_EMITIDO`:** Comprobante fiscal ya generado en Contabilium (evita dobles emisiones).
   5. **`SIN_DIAGNOSTICO_CON_INFORMACION_DISPONIBLE`:** Ningún error local encontrado; solicita telemetría de Fase 2 (logs de nginx `access_rest.contabilium.log`, callbacks salientes).
3. **Validación de Existencia de Depósito:**
   * Si se envía `deposito_id`, se consulta `/inventarios/getDepositos`. Si no existe, se reporta `DEPOSITO_INEXISTENTE` y **no se inventa evidencia de stock en depósitos ficticios**.
4. **Veracidad de Descripciones (No afirmar lo no leído):**
   * Se separan los campos `datos_verificados` y `datos_no_verificados`. Si solo se envía la referencia, se aclara que no se proporcionaron datos de cliente, SKUs ni stock, sin asumir falsamente que "se encuentran correctos".
5. **Parámetro `sintoma`:**
   * Incorporado al schema (`orden_no_facturo`, `letra_comprobante_incorrecta`, `stock_no_actualiza`, `devolucion_nc_borrador`, `timeout_sincronizacion`, `general`).
